# Wiki Interest

Самостійна навичка Agent Skills для дослідження інтересу до тем у мовних розділах
Wikipedia. Допомагає обрати напрям **подальшої перевірки** для B2C-продукту:
зіставляє статті, рахує динаміку, перевіряє чутливість висновку та створює
односторінковий PDF з графіками й відтворюваними джерелами.

Вхід для агента: [SKILL.md](SKILL.md). Увесь власний код, документація,
приклади та матеріали перевірки містяться в цій директорії. Скомпільованих
виконуваних файлів, віртуального середовища та секретів у пакеті немає.

## Як користуватися через агента

Потрібні Python 3.11+ та [uv](https://docs.astral.sh/uv/getting-started/installation/).
Агенту потрібні доступ до файлів навички, запуск команд і запис результатів;
для нового дослідження — також HTTPS-доступ до Wikimedia.
Ключ LLM API для скриптів не потрібен: доступ до моделі забезпечує середовище агента.

Установіть навичку один раз для свого агента, а далі пишіть завдання звичайною
мовою. Блоки `sh` нижче виконуються **в терміналі**; блоки `text` — це
**повідомлення в чаті агента**, їх не потрібно виконувати в терміналі.

### Codex

[Codex завантажує особисті навички](https://learn.chatgpt.com/docs/build-skills)
з `~/.agents/skills`. Для першого встановлення на macOS або Linux:

```sh
mkdir -p ~/.agents/skills
git clone https://github.com/go-dvlpr/genesis-test.git ~/.agents/skills/wiki-interest
cd ~/.agents/skills/wiki-interest
uv sync --locked
```

Якщо навичка вже встановлена й доступна агенту, цей крок пропустіть.
Потрібен **увесь репозиторій**, а не лише `SKILL.md`.
У повідомленні Codex вкажіть `$wiki-interest` і завдання:

```text
$wiki-interest Порівняй інтерес до астрономії в українському та польському розділах Wikipedia за останні 24 повні місяці. Створи PDF українською, графік і короткий висновок із джерелами. Перевір результати та дай посилання на файли.
```

Можна також прямо написати: «Використай навичку wiki-interest…».
Якщо нова навичка не з'явилася, перезапустіть Codex.

### Claude Code

[Claude Code підтримує особисті навички](https://code.claude.com/docs/en/skills)
в `~/.claude/skills`. Для першого встановлення на macOS або Linux:

```sh
mkdir -p ~/.claude/skills
git clone https://github.com/go-dvlpr/genesis-test.git ~/.claude/skills/wiki-interest
cd ~/.claude/skills/wiki-interest
uv sync --locked
```

Після цього відкрийте локальну сесію Claude Code й надішліть повідомлення:

```text
/wiki-interest Порівняй інтерес до астрономії в українському та польському розділах Wikipedia за останні 24 повні місяці. Створи PDF українською, графік і короткий висновок із джерелами. Перевір результати та дай посилання на файли.
```

Це налаштування для локального Claude Code. Воно не встановлює навичку
автоматично у вебчат Claude або хмарні сесії.
Обидві команди `git clone` вище розраховані на відсутню цільову директорію.

### Що написати далі

У тому самому діалозі можна уточнювати попередній запит без ручного запуску Python:

```text
Додай чеський розділ Wikipedia до попереднього дослідження, підніми поріг росту до 20%, а тему й період залиш без змін. Повторно використай доступний кеш, створи новий звіт і поясни, як змінився висновок.
```

Або спочатку перевірити роботу на збереженому прикладі без нових запитів до Wikimedia:

```text
Використай навичку wiki-interest. Відтвори приклад examples/astronomy-uk/snapshot.json із директорії навички в новій директорії результатів. Перевір файли й покажи PDF та графік. Для відтворення не звертайся до мережі.
```

Для такого відтворення залежності вже мають бути встановлені.
У новому запиті достатньо вказати тему, мовні розділи Wikipedia, період і мову звіту.
Наприклад, «PDF російською» або «PDF англійською» змінює мову PDF і графіка,
але не обрані розділи Wikipedia. Підтримуються українська, російська та англійська;
детальний технічний додаток Markdown залишається англійською.

### Що зробить агент і де знайти результат

Агент прочитає `SKILL.md`, підбере сутність Wikidata, перевірить відповідні статті,
створить план, запустить збір даних і формування звіту, а потім перевірить файли
командою `verify`. Знати QID чи вручну вводити команди скриптів не потрібно.
Якщо тема неоднозначна або мови не задані, агент може попросити уточнення.

Приклади навички зберігають нові звіти в `runs/<назва-дослідження>/` усередині
директорії навички. Агент має повернути точні шляхи або посилання на
`report.pdf` і `chart.png` та короткий висновок. Можна явно попросити зберегти
результат в іншій доступній для запису директорії. Кожне уточнення має створювати
новий план і нову директорію результатів, щоб зберегти попередній звіт.

Якщо агент не знаходить навичку, перевірте наявність `wiki-interest/SKILL.md`
у його директорії навичок і вкажіть абсолютний шлях до файла в повідомленні.
Якщо скрипти не запускаються, перевірте Python, `uv`, встановлення залежностей
та доступ агента до файлів, термінала й потрібної мережі.

## Сумісність із Claude та іншими агентами

Навичка використовує відкритий формат [Agent Skills](https://agentskills.io/specification)
і звичайні Python-скрипти. Код не залежить від Codex або SDK певного постачальника
моделей. Збережені дослідження можна відтворювати без мережі.

Інший агент із підтримкою Agent Skills та виконання Python може користуватися цим
самим пакетом. Без автоматичного завантаження навичок можна явно передати шлях до
`SKILL.md` агенту з доступом до файлів і термінала. Самого текстового чату або
окремого запиту до LLM API недостатньо: середовище має виконувати команди та
зберігати результати. Доступність інструментів і мережі залежить від середовища.

Фактичний наскрізний прогін виконано в Codex на `gpt-5.6-luna`. Окремий прогін на
Claude ще не проводився; сумісність із Claude Code ґрунтується на підтримуваному
форматі та незалежному від моделі коді.

## Перевірка з термінала

Це альтернативний спосіб роботи без агента. Для окремої копії проєкту:

```sh
git clone https://github.com/go-dvlpr/genesis-test.git wiki-interest
cd wiki-interest
uv sync --locked
uv run --locked python scripts/wiki_interest.py replay \
  --snapshot examples/astronomy-uk/snapshot.json --out runs/offline-demo
uv run --locked python scripts/wiki_interest.py verify --directory runs/offline-demo
```

Якщо репозиторій уже є, перейдіть у його директорію та виконуйте команди з
`uv sync --locked`. Після встановлення залежностей цей приклад працює без мережі.
Відкрийте `runs/offline-demo/report.pdf`. Для повторного запуску оберіть нову
директорію замість `runs/offline-demo` в обох командах.

## Нове дослідження з термінала

```sh
uv run --locked python scripts/wiki_interest.py search --query astronomy
uv run --locked python scripts/wiki_interest.py plan \
  --topic 'Астрономія: увага до теми' --qid Q333 --languages uk pl \
  --months 24 --report-language uk --output runs/astronomy-plan.json
uv run --locked python scripts/wiki_interest.py run \
  --plan runs/astronomy-plan.json --out runs/astronomy
uv run --locked python scripts/wiki_interest.py verify --directory runs/astronomy
```

`plan` показує вибрані статті: агент має перевірити відповідність темі до
інтерпретації. Підтримуються власні теми через пошук Wikidata, кошики до восьми
сутностей, до шести мов, явні періоди та змінювані критерії росту й обсягу.
Повторний `--qid` додає тему до одного кошика. Щоб порівняти різні теми окремо,
створіть окремі плани. `--report-language en|uk|ru` задає мову PDF і графіків;
детальний технічний додаток Markdown та поля JSON залишаються англійською.

Для уточнень створіть новий план: змініть мови, період, QID,
`--growth-threshold` або `--min-views`. Дані повторно використовуються з кешу;
`--offline` забороняє мережу, `--refresh` явно оновлює джерела. Попередній
звіт не перезаписується. При 429 програма дотримується Retry-After; після довгої
паузи повторний запуск продовжує роботу завдяки збереженому кешу.

## Що входить до результату

Кожне дослідження створює PDF, PNG, Markdown, CSV, `analysis.json`, повний
`snapshot.json`, точні URL і час отримання в `sources.json`, а також хеші
файлів. `verify` повторно рахує метрики з оригінальних відповідей API.

Готові приклади за вересень 2024 - серпень 2026:

| Приклад | Що демонструє |
|---|---|
| [Астрономія, uk](examples/astronomy-uk/report.pdf) | Повний запит, спад уваги, перевірка стійкості |
| [Астрономія, uk + pl](examples/astronomy-uk-pl/report.pdf) | Уточнення мов і порогу до 20%, повторне використання даних |
| [Інтервальне голодування, pl + cs](examples/fasting-pl-cs/report.pdf) | Немає польського sitelink для обраної сутності; порівняння обмежене |
| [Вивчення англійської, de + es + fi](examples/english-de-es-fi/report.pdf) | Явний тематичний проксі та малі обсяги; не прямий попит на застосунок |

Відсутній sitelink означає відсутність перевіреного відповідника в цій схемі,
а не доказ відсутності будь-якої релевантної статті. Для прикладу англійської
мови de/es/fi обрані як демонстраційні мови, у яких є відповідники Q130192.
Це не рекомендація цих ринків і не заміна мов, які вибрав би користувач.

## Чому рішення побудовано так

Python використано через компактну реалізацію аналізу, графіків і PDF.
HTTP, кеш, валідація та арифметика спираються на стандартну бібліотеку;
Matplotlib і ReportLab відповідають за візуалізацію. Немає сервера, БД,
оркестраційного фреймворку або викликів LLM усередині обчислень.

Недорога модель обирає сенс теми та пояснює вже пораховані результати.
Код визначає пропуски, виконує обчислення й формує файли. Це зменшує вимоги
до моделі та дозволяє перевірити кожне число незалежно від її відповіді.

Обрано прозорі описові правила замість неперевіреного «індексу ринку».
Порівнюються однакові календарні місяці, абсолютні перегляди та частка в
загальному трафіку розділу. Перевірка з вилученням кожної пари місяців
показує залежність результату від окремого місяця. Це не довірчий інтервал.

## Перевірка та межі

```sh
uv run --locked pytest -q
uv run --locked ruff check .
uv run --locked ruff format --check .
```

Живий сценарій та уточнення виконано незалежним агентом `gpt-5.6-luna`.
Збережено запити, команди, stdout/stderr і артефакти. Деталі, результати
автоматичних перевірок і межі цього експерименту:
[evaluation.md](references/evaluation.md).

Перегляди не вимірюють покупців, унікальних читачів або готовність платити.
Мова Wikipedia не дорівнює країні. Аналіз поточних назв не реконструює всі
перейменування й перенаправлення. Відсутні дані не стають нулями. Брак
сигналу росту не доводить відсутності комерційного попиту.
